# Null tests against FL Studio

How Chan Sampler is checked against FL Studio's Sampler: the same notes go through both, one is subtracted from the
other, and the residual is reported (below −60 dB counts as a match; FL's 16-bit export floor is about −65 to −95 dB).
The results are in [NULLTESTS.md](../NULLTESTS.md) (generated by `nulltest.py --report`), the measurements in
[MEASUREMENTS.md](../MEASUREMENTS.md) and the measured data in
[measurements/](../../measurements).

Requirements: FL Studio (closed while rendering: a running FL swallows the command-line render, so the render queue
waits while it is open; set `FL_DIR` when it is not in its default install folder), Python 3.12 or newer with `numpy`
(`pip install -r requirements.txt` at the repository root), and Release builds of the plug-in and of `CsRender` (see
the main README).

## Layout

Every script sits in this folder and runs from it (`python <script>.py`, or `python -m <script>`). The names say what
each does:

| Name | What it is |
|---|---|
| `cs_ref.py` | the harness: in-FL pairs, FL's Sampler on channel 1 and the Chan Sampler VST3 on channel 2 of one project, rendered once by FL and subtracted |
| `nulltest.py` | the offline suite (FL's Sampler alone against `CsRender`); `--report`, which writes NULLTESTS.md; `--vst3`, the built VST3 in `RefRender` against `CsRender`, without FL (the null step of the check script) |
| `first_null.py` | one in-FL pair: proves the harness, FL, the build and the queue (`--dry` without FL) |
| `cases_<topic>.py` | the case lists: each defines `CASES` |
| `measure_`, `probe_`, `fit_`, `compare_`, `check_`, `null_` scripts | how each model in the plug-in was found and is checked (below) |
| `render_signals.py`, `render_stretch_signals.py` | write the test signals into `signals/` (generated, never committed) |
| `<topic>_lib.py` | shared code: `queue_lib` (the render queue), `ref_solo_lib` (FL's Sampler alone), `project_lib` and `project_file_lib` (FL project files), `channel_lib` (the Chan Sampler channel), `wav_lib`, `paths_lib`, `nulltest_lib` (generic residual and signal helpers), and the models the fits use (`filter_lib`, `onepole_lib`, `resample_lib`, `transfer_lib`, `reverb_lib`, `reverb_b_lib`, `stretch_lib`, `stretch_metrics_lib`) |

FL's renders are cached in `renders/` (FL's Sampler alone) and `renders_fl/` (in-FL pairs), ours in `ours/`; none of
them are in the repository (`-f` re-renders where a script offers it).

Every FL render goes through `queue_lib.py`. Each render keeps a record beside its WAV (`<name>.render.json`) with a
key made of the project (built with bare sample names, so a moved repository keeps its renders), the sample, the Chan
Sampler VST3 (in-FL pairs only) and FL's version; a render whose record matches is reused, a WAV without a record is
adopted when its project is byte-identical and nothing it depends on is newer, and the rest is rendered again with the
reason printed. On Windows FL renders on a desktop of its own, so its window does not take over the screen while a
queue runs (the renders are byte-identical; `FLQUEUE_VISIBLE=1` shows them again, for a render that hangs on a
dialog). A failed render is retried (three attempts), and so is one that ends before its last note (FL sometimes
stops early), a hung FL is killed after the timeout, `renders*/queue.json` makes a stopped run resumable, and one lock
keeps two queues apart. A plug-in rebuild makes every in-FL pair stale ("newer than the render: Chan Sampler.vst3"):
after a DSP change render again; after a rebuild that changed no audio pass `adopt=True` (`--adopt`) once, or
`plugin_dep=False` (`--no-plugin-dep`).

```text
python first_null.py --dry                                    # the tools, the signal, the plan for one pair; FL not started
python -m queue_lib cases_core cases_arp --dry                # the plan: what would render, and why
python -m queue_lib cases_core --adopt                        # trust the old WAVs once (a rebuild that changed nothing)
python -m queue_lib --status                                  # after a stopped run: what is cached, what failed
python -m queue_lib cases_offline --kind fl                   # FL's Sampler alone (the offline cases' FL half)
python -m queue_lib --selftest                                # the queue's own test, no FL needed
```

## In-FL tests (the reference)

FL's Sampler on channel 1 and the Chan Sampler VST3 on channel 2 of one project, rendered once by FL from its command
line; the two halves are subtracted as heard in FL, with no gain correction.

```text
python -c "import cs_ref, cases_core; cs_ref.run(cases_core.CASES)"
python -c "import cs_ref, cases_core; cs_ref.run(cases_core.CASES, ['d_cut'])"   # names containing d_cut
python -m cases_untested -f                                                     # case files with a main; -f re-renders
```

| Cases | Covers |
|---|---|
| `cases_core.py` | precomputed effects, interpolation, envelopes, declicking |
| `cases_fx_sweep.py` | the precomputed effects over their whole range |
| `cases_trim_sweep.py`, `cases_trim_fit.py`, `cases_trim_short.py` | SMP START / LENGTH, trim (short: segments under FL's shortest) |
| `cases_lfo.py` | LFOs and filter modulation |
| `cases_filter_fourth_order.py` | LPx2 and SVF LPx2 |
| `cases_echo.py`, `cases_arp.py` | echo delay, arpeggiator |
| `cases_untested.py` | loops, echo Mod X / Y and fat mode, tracking, glide, polyphony, root note, FLAC / Ogg / MP3 |
| `cases_preset_import.py` | FL Sampler preset (`.fst`) import |
| `cases_stretch_time.py` | TIME with Resample |
| `cases_declick.py` | the six declicking modes (start offset, sample end, cuts) with a constant, noise and a sine |
| `cases_tempo_env.py` | the volume envelope at 65, 100 and 160 BPM (Tempo off and on), decay tension |
| `cases_e3_pitch.py` | e3 generic at −1200 … +1200 cents (see `null_e3_pairs.py`) |
| `cases_offline.py` | the offline cases (below) |

Notes: cases with more than one note use a 26-beat gap between the halves (FL's tick is 11025 / 52 samples at 130 BPM,
so only then do both sit on the same sub-sample positions; 26 beats also lines up at 65, 100, 120 and 160 BPM, set per
case with `bpm`); samples longer than the gap need the volume envelope, or FL's half spills into ours.

## Offline tests (fast)

`python nulltest.py` renders FL's half of every case in `cases_offline.py` from the command line (FL's Sampler alone)
and Chan Sampler's with `CsRender`, prints each residual and saves them to `ours/offline_results.json`;
`python nulltest.py --report` writes [NULLTESTS.md](../NULLTESTS.md) from that file without rendering, and `--dry`
prints the render plan without starting FL. `compare_offline_pair.py` compares an offline render with FL's half of an
in-FL case, for model tuning without new FL renders. The cases play at FL's unity velocity, 100: FL passes a note's
velocity to a plug-in unchanged as the MIDI velocity, so FL's 128 cannot be reproduced outside FL. The in-FL tests
remain the reference for final numbers.

## Stretch modes

The stretch modes cannot null against FL (its engine, elastique, is proprietary), so these compare behaviour: where
attacks land, how the output is built, and envelope / band-spectrum distance. Make the test signals first:
`python render_stretch_signals.py` (they are generated, bit-identical to the ones FL rendered).

| Script | Measures |
|---|---|
| `null_e3_pairs.py` | e3 generic in FL: 30 pitch cases (707 Kick, a Rhodes, a voice, two drum loops at −1200 … +1200 cents) |
| `compare_stretch.py`, `check_stretch.py` | each mode against FL's render of the same settings; every mode offline, without FL |
| `compare_stretch_material.py` | every mode on the same material at ±700 cents and MUL ×1.5 / ×0.667 (our stretcher alone, fed FL's decode of each sample) |
| `compare_stretch_modes.py` | every mode on clicks, a saw and noise: click timing and gain, band levels, whether the output is pieces of the source |
| `compare_slices.py` | the slice modes, the whole plug-in on FL's own drum loops |
| `measure_e3_attacks.py` | e3 generic's attack timing on bursts stepped through FL's 512-sample grid (PITCH and MUL), shaped bursts, and the low band's gain while an attack is held |
| `measure_soft_start.py`, `measure_split_rise.py` | where each mode puts a note that starts softly (no attack); where a mode splits its vocoder from its grains as MUL grows |
| `measure_e3_parity.py` | single-sample clicks at exactly ±1200 cents |
| `measure_grain_marks.py` | the grain modes (e3 / e2 mono, e2 speech) on pulse trains of known period: the period each splices and where its crossfades sit against the pulses |
| `measure_ratio_grid.py` | FL's stretch-ratio grid (the treble ripple's rate per MUL) and e3's splice sizes on noise, FL against ours |
| `measure_e3_lowband.py` | e3's band below the split after an attack: where FL restarts its phases (steady tones switched on by a click), and an in-FL case's low-band phase delay over time |
| `stretch_metrics_lib.py`, `stretch_lib.py` | the distances, the mode table, our stretcher run on its own |

FL's own samples are read from the FL install, never copied here.

## Measurement scripts

How each model in the plug-in was found, kept for re-measuring when FL changes and for working on the known gaps.
Most render through FL, so close it first. Their data is in `measurements/` at the repository root.

| Topic | Scripts and data |
|---|---|
| Interpolation and sample-rate conversion | `measure_kernel.py`, `fit_kernel_table.py`, `fit_window.py`, `fit_interp.py`, `measure_src_kernel.py`, `resample_lib.py`; `interp_kernel.npy`, `interp_window.npy`; signals `impulse1000.wav`, `impulses50.wav`, `imps22.wav`, `imps48.wav`, `imps96.wav` |
| SMP START fade and trim tail | `measure_head.py`, `measure_tail.py`, `measure_tail_short.py`, `measure_trim_matrix.py`, `fit_trim_end.py`, `compare_trim.py` (they write their own signals); `head_matrix.npy`, `tail_matrix*.npy`, `trim_matrix_span*.npy`, `jump_*.npy` |
| Envelopes, tempo switches | `probe_tempo.py`; `probe_env_tick.py` (FL's per-tick envelope: stage ticks, jump rate, at eight tempos), `probe_env_time.py` (the knob's real times from attacks at six tempos; `env_times.txt`), `probe_env_hold.py` (`env_hold_sweep.txt`); `attack_times.json`, `env_time_table.json` (the earlier 130 BPM table); signals `dc6.wav`, `dc20.wav`, `dc70.wav` (written by `probe_env_time.py`) |
| LFOs | `measure_lfo.py`, `measure_lfo_speed.py`; `lfo_periods.json`, `lfo_speed.json`, `lfo_pulse_ramp.npy` |
| Arpeggiator timing | `compare_arp.py`, `measure_arp_time.py`, `measure_arp_period.py`, `probe_arp_hold.py`; `arp_ticks_dense.txt` |
| Filters | `filter_lib.py` (biquads, the state-variable filter), `onepole_lib.py` (one-pole), `transfer_lib.py` (transfer functions); `res_r.npy`, `svf_map.json` |
| Precomputed reverb | `fit_reverb_pulses.py`, `fit_reverb_combs.py`, `fit_reverb_deconv.py`, `fit_reverb_b.py`, `fit_reverb_b_levels.py` with `reverb_lib.py` and `reverb_b_lib.py` (the impulse response decomposed into pulses, combs and allpasses) |
| Robustness | `check_robust.py` (host rates, mono / 16 / 24-bit / 48 kHz and very long files), `check_corrupt_files.py` (damaged and unusual files must not crash); both write their own test files |
| FL project format | `probe_param_fields.py`, `probe_events.py`, `probe_project_diff.py` (find where FL stores a setting by diffing saved projects); `local/t_base.flp`, a base project of your own (render it in FL for `local/t_base.wav`); `local/` holds the files FL writes and is never committed |
| Sample view and formats | signals `freqsteps.wav`, `freqsweep.wav` and a drum sample of your own (spectrum and colourful-waveform captures), `bits16_1ch.wav`, `bits24_2ch.wav` (format badge), `cue_tone.wav`, `strc_*.wav` (region / slice markers), `smpl_loop.wav` (embedded loop) |
| Slice starts | `measure_slice_starts.py` (Slice map: which channel's zero crossing FL picks, and whether cue / slice markers move; it writes its own signals) |
| Stretch-mode signals | `render_stretch_signals.py` writes `ons_meta.json`, `grid_meta.json`, `grid2_meta.json` beside the measured data |

`local/vst_wrapper.bin` holds the two FL channel events of the VST wrapper that `channel_lib.py` turns into a Chan
Sampler channel. FL writes it, so it stays local: save it from an FL project of your own that holds Chan Sampler.
